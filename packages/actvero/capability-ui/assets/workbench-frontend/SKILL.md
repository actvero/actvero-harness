# 工作台前端规范

面向开发工作台界面的 Agent。让工作台与 ACTVERO 的公共交互一致，同时保留业务布局、品牌表达和专用交互的自由。本 Skill 只负责前端设计与验收；包格式、AI、存储和安装按工作台开发规范处理。

## 先确定设计依据

读取项目已有的 DESIGN.md、界面代码和用户指定的参考。业务目标不明确时先澄清，不从模板推断需求。已有明确设计时沿用，不为使用本 Skill 重做界面。新建项目把已确认的最小流程、页面、首次入口及设计选择写入 DESIGN.md；记录当前决定，不记录讨论过程。简单页面简写即可，不要求用户填写设计表。

采用以下一种方式，缺省建议原生风格；用户已有偏好时直接执行，不增加一次审批：

- 原生：复用宿主颜色、字体、图标和基础组件，适合管理、表单、报表与日常工具。
- 品牌：保留公共交互和组件语义，在业务区使用有依据的强调色、插画与排版。
- 自定义：画布、编辑器、游戏等可自定业务区布局与视觉；仍兼容主题、容器、键盘和宿主公共入口。

DESIGN.md 写明实际采用的方式、复用的组件、关键页面和例外原因。它是项目设计依据，不是必须全部勾完的通用问卷。个性化不需要逐项向用户申请；影响业务流程或与用户明确要求冲突时才澄清。

## 复用真实组件与语义

先查当前工具链真实导出的组件和已有同类页面，再写界面。源码仓库的 `packages/client/ui-primitives/src/index.ts` 是公共组件入口；本地项目的 `.actvero/toolchain.json` 记录源码位置。运行环境中的开发 Skill 提供同次构建的 API 快照，不能根据组件名猜参数，不能使用未导出的内部实现。

按钮、输入框、选择器、菜单、弹窗、提示、开关和标签优先使用 `@deepseek-ai/dsh-client-ui-primitives`。图标沿用宿主图标体系，包图标用于业务身份；图标按钮保留可访问名称。宿主已提供导航、AI 会话、权限与模型选择时直接复用，不在业务区复制一套。文案通过工作台语言字典维护。

从当前宿主的主题变量及组件样式中选取颜色、边框、背景和字号，在 DESIGN.md 记录实际名称；不要把不同组件层的变量前缀混用，也不要臆造 token。业务样式局部生效，避免覆盖宿主全局 CSS。保留明暗主题的文字与边框对比度，避免硬编码整页白底。原生风格通常使用常规或中等字重；大段粗体、重阴影、过大的空隙和重复卡片会降低信息密度。

## 按工作台容器设计

先规划业务主界面，再决定何时显示 AI。无会话时也有明确入口；需要 AI 时复用宿主会话显示能力。完整页面、对话旁的业务区和悬浮预览共用业务状态，布局依据自身容器宽度重排，不能只用整窗断点。

表单和列表在窄容器优先纵向排列；名称可截断，正文可换行，操作保留可点击面积。长中文、英文、路径和错误信息不能造成单字竖排、控件裁切或整页横向溢出。预览是缩小查看，不能依赖预览内完成精细操作；需要操作时保留进入完整工作台的宿主入口。

顶栏由工作台的 Header 完整渲染；宿主只保留公共返回与窗口控制。不预设面包屑、图标、名称或下拉导航，按业务选择布局与控件；复用原生组件不等于强制套用固定顶栏模板。

定义首次、空数据、加载、失败、禁用和成功状态。加载时保留可用内容，错误就近说明恢复办法；普通切换不额外堆叠成功通知。菜单、弹窗使用宿主的定位、焦点与 Escape 行为；触屏和键盘不依赖 hover 才能发现必要操作。

## 视觉验收

构建成功后实际查看界面，至少检查本次涉及的完整页面、窄容器、侧栏展开/收起、浅色/深色和真实长度内容；涉及 AI 时再检查无会话及已关联会话。验证图标、按钮间距、文字层级、菜单边缘、键盘焦点和错误反馈。与 DESIGN.md 及所复用的宿主页面对照，修正后记录证据和仍待验证的状态。DOM 或源码中存在按钮不等于用户能看到、点到；仅通过类型检查不能宣称视觉验收通过。
