# 构建与验收

Mac 目标使用 macOS，Windows 目标使用 Windows。Node 进程架构要和预设匹配。Windows x64 预设可在已经准备好相应工具链的 Parallels Windows 中，用锁定 x64 Node 构建。在 Windows 本地磁盘运行，保留同一源码提交的构建目录以复用增量缓存。使用现有 Windows 启动包时，可以在相容的本地源码目录导入配置 ZIP，再用 `build --preset kit:<包ID>/win-x64`。旧的三套一键入口继续用于自身随包的预设。

1. 查当前 Git 提交、源码状态、Node 架构和可用预设。确认现有工作是否要一起构建。遇到错误架构，切换到正确环境后继续。
2. 启动构建并看日志。正式打包各阶段可能长时间少量输出。用最近进程活动、产物或退出状态确认；CPU 有活动只能说明进程在运行。
3. 同一个工作目录每次只运行一场构建。若收到锁错误，读取所列 PID 和日志，核对是否还有子构建进程。进程全退出且用户授权清除残留锁后，才移除该锁。保持失败现场和已有安装包。
4. 打包程序会在导出前执行归档运行时检查。构建包 CLI 再用 `release.json` 对成品复算 SHA256。将构建日志和构建产物放在各自路径，构建结果从本次命令的 `output` 和 `artifacts` 读取。
5. 对 AI 身份作真实对话验收时，在独立数据目录启动目标构建，用新会话询问「你是谁」，再发一个会使用现有工具的普通任务。检查默认版和定制版各自的回答、运行时工具仍可用。把这项结果与静态预检和归档检查分别记录。
