# 品牌构建访谈

面向需要创建或修改桌面品牌包的 Agent。在用户已经给出完整规格时，跳过已明确的问题。

1. 确认应用显示名称和版本。如果是更新某个现有品牌，读取该品牌配置中的 `product.id` 和 `product.applicationId`。新身份需要与现有应用并存时，选择不同的应用标识，预览给用户确认。显示名称可改，安装身份由应用标识控制。
2. 确认默认平台地址与安装包目标，例如 Windows x64 和 Apple Silicon Mac。平台地址会进入安装包。配置使用 HTTPS 或仓库允许的本机回环 HTTP。把版本和目标写清楚。
3. 确认应用图标与侧栏视觉。应用图标和托盘需方形，侧栏字标可为横版。支持 SVG 和 PNG，优先复用用户提供的素材。没有素材时给出继续用默认图标和后续提供素材两个选项。有图像工具且用户希望制作时，再按确认的方向生成。
4. 确认 AI 身份。问「别人问『你是谁』时，你希望它怎么回答？」给出「用默认身份」和「自定义一段身份」两个选项。用户想自定义时先了解角色、面向的人、主要工作和对外称呼，再展示一段原文。仅修改身份，使用 `assistant.identityPrompt`。这个字段只接进 `harness:identity`，空白即用默认身份。
5. 发出确认摘要。把产品和打包配置用简短的表格或清单列出，用代码块原样展示身份说明。如果内容不合适，修改后再次确认被改动的字段，再生成规格 JSON。

## 例子

用户已经提供名称、平台和 Windows 目标，缺图标和身份时，可以直接问。

- 「应用图标想用现有素材、沿用默认图标，还是先做一版给你挑？」
- 「当用户问『你是谁』，是用默认身份，还是叫『示例公司的办公协同助手』？如果用后者，我可以根据你的使用场景起草一段。」

确认身份时展示下面这样的原文。

```text
你是示例公司的办公协同助手，运行在示例 Harness 中。你帮助团队整理资料、起草文档和跟进协作。用户询问你是谁时，称自己为“示例公司的办公协同助手”。
```
