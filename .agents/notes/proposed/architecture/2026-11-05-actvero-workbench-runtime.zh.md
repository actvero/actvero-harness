# Agent Note: Actvero 工作台运行上下文与本地专家

Status: proposed

[English](2026-11-05-actvero-workbench-runtime.md) | 中文

## 问题

本文面向实现 Actvero 工作台框架及业务插件的开发者，用于确定宿主应提供的能力、工作台作者保留的自由，以及后续接口实现的验收范围。设计方向已确定，统一运行上下文及内置专家接入接口仍待实现；本文不代表这些接口已经发布。

工作台作者需要在正常的应用开发中使用宿主的原生对话、本地专家、用户身份和服务授权。业务界面、数据保存、模型来源和工具接法各有需求，统一业务流程或要求先发布云端专家会限制本地工作台。

现有宿主行为见[客户端工作台](../../../../actvero/workbenches.zh.md)，现有专家与平台模型能力分别见[专家参考](../../../../packages/actvero/experts/README.zh.md)和[模型适配参考](../../../../packages/actvero/model-gateway/README.zh.md)。这些已有服务是接口实现的复用基础。

## 提案

框架提供工作台运行上下文、生命周期入口及可选宿主能力，工作台作者按普通应用方式开发业务。运行上下文由现有 Cordis 服务、Host Remotes 和 Client Slots 组合，不另建 Agent 执行器、登录系统或插件管理器。

| 宿主能力 | 工作台作者可使用的内容 |
| --- | --- |
| 身份上下文 | 当前用户、当前组织及业务需要的身份资料 |
| 服务授权 | 平台授权请求、指定服务的短期凭证或带授权的服务调用 |
| 原生对话 | 创建、恢复、嵌入对话，传入明确选择的项目上下文 |
| 本地专家 | 注册工作台附带的专家定义，或引用已有本地专家 |
| 可选扩展 | 业务工具、Skill、MCP、CLI 及宿主允许的其他服务 |

工作台自行选择界面布局、业务流程、数据保存方式、模型来源及工具实现。平台模型、自配服务和本地程序可以按需组合。采用专家、素材库、Skill、MCP 或 CLI 均不是所有工作台的共同前置条件；不依赖平台授权的本地功能可以独立使用。

### 本地专家与生命周期

工作台启动时获得初始化入口，可以注册或准备一个或多个内置专家。专家定义随本地工作台分发，可以只在该工作台内部使用，无需先上传中台或进入全局专家市场。宿主管理注册及注销，避免重载后残留或重复注册。

加载专家定义、打开会话和执行模型请求分别控制。工作台作者决定触发时机、入口和展示方式，宿主不统一规定助手按钮或常驻对话区。调用时可以指定本地专家并传入项目上下文，创建或恢复匹配的会话，沿用现有专家和会话的版本、持久化及权限语义。

### 身份与授权上下文

身份资料可供工作台代码读取；服务授权由宿主管理，并继续受目标服务的权限约束。主账号的长期登录凭据保留在宿主管理范围，工作台按指定资源申请短期授权或调用授权请求接口。外部服务使用其支持的认证方式，不假定同一登录令牌适用于所有服务。

上下文与当前账号和组织绑定，切换、退出或撤权后旧授权失效，后续调用重新取得适用的上下文。运行上下文不会自动整体发送给模型；作者主动选择需要的业务信息，模型可见内容继续遵循宿主记录机制。

## 曾考虑的替代方案

- 固定每个工作台的专家、Skill、MCP 和 CLI 组合：业务所需能力不同，因此保留可选组合与正常应用开发方式。
- 让每个工作台独立保存登录凭据：会重复身份、组织切换和续期逻辑，因此统一复用宿主授权服务。
- 要求专家先发布到中台：会阻碍纯本地分发及工作台内部助手，因此同时支持随包定义和已有本地专家引用。

## 验收标准

- 普通本地工作台可以注册和运行，不以专家发布、平台模型或特定工具协议作为共同前置条件。
- 工作台启动后可准备内置专家，重载和卸载后注册得到清理；启动准备不会隐式等同于发起模型请求。
- 作者可以自由放置对话入口，指定专家与项目上下文，正确创建或恢复对应会话。
- 工作台可以读取必要的当前身份资料并调用获授权的服务；服务端继续校验资源权限，长期登录凭据不进入工作台页面或项目文件。
- 账号、组织和授权变化后，旧上下文不能继续用于新的服务请求；运行上下文不会自动进入模型提示词。
- 素材库与创作插件作为接入验证对象，保留各自的业务界面、数据服务和可选工具组合；真实平台和模型调用单独验收。

## 风险

运行上下文若暴露过多宿主内部实现，会扩大兼容维护范围；公共接口需要版本化并明确能力可用性。具体 API 名称、类型、能力声明和错误协议在实现时确定。

本地专家定义及其依赖可能在更新后变化，恢复会话需要遵守已记录的专家版本和权限语义。身份资料、授权凭证与模型上下文混用可能造成资料泄露或跨组织误用，三者必须分别处理。
