# 工作台宿主扩展架构规划

[English](workbench-architecture-plan.md) | 中文

本文面向工作台框架、SDK、开发工具和专家集成的研发人员，用于确定架构、拆分交付和验收；工作台作者可据此了解计划开放的能力。阶段一已实现兼容声明和现有提供者的异步释放管理；阶段二已交付顶栏、面包屑与共享视图状态，其余宿主扩展和阶段三至六仍待实施，本文中的宿主扩展接口并非全部可用。当前开发、打包和安装以[工作台开发指南](workbench-development.zh.md)为准；已有本地运行能力见[工作台运行生态实施规划](workbench-runtime-plan.zh.md)。

## 1. 产品形态与职责

工作台继续是用户安装、打开和管理的产品单位，技术上采用由宿主管理的插件包。一个包可以同时包含业务界面、Host 服务、宿主界面扩展和可选专家资源，通过现有 Plugin Manager 统一安装、启停、更新和卸载。用户不需要分别安装工作台和另一份配套插件；开发者不需要另外实现一套 AI 客户端。

宿主提供稳定的运行环境、原生 AI 与会话、公开身份与受控平台请求、资源和数据目录，以及明确的界面扩展接口。工作台作者决定业务界面、导航、数据格式、对象组织和 AI 操作方式，可以使用专家指令、Skill、MCP、CLI 或业务工具；AI 是可选能力。

“工作台使用插件机制”不意味着获得任意修改宿主的产品接口。支持的扩展通过注册表和生命周期管理；操作宿主私有 DOM、替换内部组件或修改 Agent 循环不属于工作台 SDK。原生 Host/Client 插件代码具有其运行进程的权限，Cordis 作用域负责释放资源，不构成不可信代码的安全沙箱。

## 2. 当前基线与主要缺口

以下列出基础能力与后续目标；兼容声明和提供者释放的当前行为见[运行时说明](../packages/actvero/capability-ui/README.zh.md)。

| 领域 | 当前基础 | 下一阶段改造 |
| --- | --- | --- |
| 包管理 | 本地包校验，复用 Plugin Manager 安装、启停和移除 | 将包内贡献、依赖和兼容性纳入同一生命周期 |
| 业务运行 | Host provider、Client 注册、独立目录和可选 JSON 适配器 | 明确工作台、业务对象、视图、会话的作用范围 |
| AI | 原生对话、会话绑定、专家指令与 Skill/MCP/CLI 加载路径 | 向作者提供统一入口和可恢复的准备状态 |
| 布局 | 全页工作台、AI 浮窗、工作台预览及显示偏好 | 增加顶栏扩展，保持宿主公共操作一致 |
| 输入与设置 | DSH 已有原生引用序列化、输入扩展和设置插槽 | 将原生能力接入工作台 SDK，不另造输入框 |
| 开发交付 | plain/ai 模板，开发与前端 Skill，校验和打包工具 | 增加扩展声明、加载检查和跨会话验收 |

当前关键实现位于 [Host provider](../packages/actvero/capability-ui/src/workbench-provider.ts)、[运行时](../packages/actvero/capability-ui/src/workbench-runtime.ts)、[Client 注册](../packages/actvero/capability-ui/src/client/workbenches/register.ts)和[包管理](../packages/actvero/capability-ui/src/client/workbenches/management.ts)。原生输入能力见[引用接口](../packages/client/ui-conversation/src/client/contract/input.ts)和[引用服务](../packages/client/ui-reference/src/client/index.ts)。下一阶段应复用这些基础，逐步替换工作台专用的临时接线。

## 3. 运行分层

| 层次 | 负责的内容 | 不承担的内容 |
| --- | --- | --- |
| 包协议与 SDK | 类型、能力声明、版本要求、Host/Client 入口、扩展注册 | 具体业务页面和数据库结构 |
| Host 运行时 | 准备环境、会话绑定、专家和工具作用范围、目录、受控服务 | 前端布局和业务流程 |
| Client 宿主 | 工作台视图、顶栏、浮窗、原生对话、输入引用和设置入口 | 直接读写作者的业务数据库 |
| 包管理 | 校验、安装记录、启停、升级、回退和卸载状态 | 业务数据迁移和平台发布审核 |
| 专家适配 | 指令及依赖解析、按会话激活、工具执行上下文 | 强制作者采用某一种 AI 操作方式 |
| 工作台实现 | 业务界面、对象与存储、业务操作、可选专家及依赖 | 自行复制宿主账号、聊天和安装系统 |

上述首先是职责划分，不要求立即创建六个新包。每项共享能力要同时定义服务接口、提供者和消费者；只有发布、依赖或生命周期需要独立演进时再拆包。继续使用 Cordis 的注册和释放机制，通过受支持的 `dsh` profile 启动运行环境，不引入工作台自行启动宿主的旁路。

## 4. 一个包内声明哪些内容

保留现有本地安装入口和 `.tgz` 交付方式；远程分发将来下载同一种包并进入同一安装流程。本阶段不增加另一套 ZIP 运行格式，也不要求本地工作台有 GitHub 仓库。

包声明分为以下几类；具体字段在协议实现时确定，不应把本文名称当作可调用 API。

| 声明 | 要求 |
| --- | --- |
| 身份与兼容 | 稳定工作台标识、名称、图标、版本、包协议版本和宿主 API 要求 |
| 入口与资源 | Host/Client 入口、业务视图、静态资源、预览和本地化资源 |
| 宿主扩展 | 顶栏、命令、设置、输入引用、消息或工具结果展示及各自作用范围 |
| AI | 是否启用原生 AI、随包专家位置、明确声明的 Skill/MCP/CLI 与业务工具依赖 |
| 平台能力 | 使用的受控平台服务及权限，不包含账号凭据 |
| 配置与数据 | 配置说明、资源目录需求、数据兼容与迁移说明 |

未声明 AI 的工作台可以直接使用业务界面；AI 依赖失败不应使无关业务界面消失。必需业务依赖缺失则应报告具体原因并停止相应功能，不能伪装加载成功。安装校验覆盖入口、资源、声明一致性与版本兼容；运行验收还要覆盖实际模块加载，不能以归档格式合法替代加载成功。

## 5. 宿主开放的扩展能力

### 顶部功能栏与业务视图

宿主保留返回工作台管理、侧栏控制、窗口操作和统一的 AI 入口。竖线右侧提供工作台身份、面包屑、状态和操作区域：例如“协作白板 / 我的图纸 / 产品流程”，右侧放保存状态、导入和导出。插件可以按当前页面更新这些内容，避免业务区再出现一排重复标题。

标题栏布局、窗口拖动区域、焦点、窄窗口折叠和宿主公共入口由 Client 管理；工作台提供内容与命令。标准按钮、菜单和面包屑优先采用原生组件，确有复杂需求时允许在指定区域注册自定义组件。自定义范围不能覆盖窗口控制或吞掉退出工作台的入口。

业务主视图继续由作者自由实现，支持画布、表格、报表和普通页面。全页与小预览共用业务对象和数据，切换显示方式不创建另一份数据实例。插件可为小预览提供适合的呈现方式；默认预览不应把大界面压成不可用的嵌套滚动区域。

### 原生输入框与上下文引用

SDK 适配 DSH 的原生引用来源、序列化、历史展示和打开引用接口。白板选区、视频片段、文档段落可以表现为输入框里的引用项，用户可以查看、移除，再发送消息；工作台不必接管整套输入框，也不需要让用户复制内部编号。

引用绑定工作台、业务对象和版本信息。作者提供可序列化的引用说明、必要内容快照以及可选的重新打开行为；宿主负责草稿、附件、发送和日志。自动附带当前选区应由工作台明确启用并在输入框可见，用户移除后不能因重新渲染立即加回来。引用只是上下文，不自动授予文件、模型或业务写入权限。

扩展如需补充发送上下文，应走受控的提交准备阶段，记录补充来源并形成最终消息快照。不得在发送后偷偷改写用户输入或在后台改变本次消息指向的业务对象。

输入引用适配应以原生 `slash/input-insert-reference` 和 `InputTriggerController.serializeReference` 为入口，将引用插入目标会话当前的输入实例，而不是全局当前对话。引用解析与发送必须固定对象标识、修订号及内容快照；用户取消引用后不自动补回。已通过 API 1.2.0 的 `workbench.reference()` 封装显式插入，使用原生输入 facade 的同一插入事务与序列化来源；已覆盖草稿恢复、发送日志、卸载后的历史展示和目标会话隔离。自动附带选区、发送前钩子和重新打开对象仍待后续设计。未启用模型标题生成时，原生兜底标题仍会截取引用序列化文本；后续需提供宿主统一的可读标题投影，不由工作台改写原始消息。

### 设置、命令与消息展示

工作台可以在宿主设置中注册自己的面板，也可在业务内打开对应面板。安装启用的设置属于工作台级；当前图纸或项目的设置属于业务对象级，由作者存储和管理。设置命名、权限与清理规则必须区分这两种范围。

命令可以挂到功能栏或受支持的命令入口。自定义消息及工具结果展示复用原生扩展点，提供默认只读展示，以便工作台停用或卸载后历史对话仍可阅读。普通对话也能使用宿主提供的列出、打开和查看工作台状态工具；打开指定视图不等于自动发送消息或执行业务操作。

### AI 入口

启用 AI 后，宿主提供原生浮窗、收起后的品牌图标、全屏对话和关联对话切换。工作台可以通过 SDK 请求打开 AI 并携带当前业务上下文，无需再放置重复的通用“使用 AI”按钮。针对具体业务的“解释选区”等动作可以保留，但必须表明是否只准备草稿或立即执行用户已请求的操作。

## 6. 工作台、业务对象与会话

工作台包、运行环境、业务对象和对话是不同的概念。宿主的默认运行实例提供目录与服务，不规定一个工作台只能有一张图纸或一个项目；作者在自己的存储里管理这些对象。宿主只保存关联需要的稳定对象标识、显示信息和恢复信息，不建立统一业务项目数据库。

| 使用场景 | 预期行为 |
| --- | --- |
| 普通新建对话 | 默认不继承上次工作台及其专家环境 |
| 工作台内新建对话 | 显式绑定当前工作台和业务对象，按声明准备专家环境 |
| 打开已有关联对话 | 恢复该对话保存的业务对象，不改用其他窗口当前选中的对象 |
| 同一对象开启多条对话 | 可以共享业务数据，各条对话的历史和执行上下文独立 |
| 切换图纸或项目 | 更新当前视图；正在执行的对话和工具仍操作原先绑定对象 |
| 收起 AI 或工作台预览 | 只改变显示状态，不解除绑定，也不取消正在执行的任务 |

布局偏好与业务绑定分别存储。宿主记忆浮窗位置、展开状态和侧栏偏好；开发者的默认布局仅在没有用户偏好时生效。删除业务对象后，关联历史仍能打开并说明对象已不可用，不能悄悄新建同名对象替代。

## 7. 专家环境与一次发送的过程

打开 AI 时，运行时先准备目录和当前业务对象，创建或恢复明确关联的会话，然后解析随包专家和依赖。隐藏专家指“不额外要求用户选择专家”，不表示隐藏权限、运行状态或模型可见内容的来源；用户仍能查看该工作台启用的能力。

一次发送按以下顺序完成：

1. 从当前草稿取得工作台绑定、业务对象与用户保留的引用项。
2. 固定对象标识、版本和选区，执行可取消的引用序列化；后续切换页面不改变这次发送的目标。
3. 校验该会话所需专家与工具已准备，按当前权限检查访问范围。
4. 将最终用户消息、引用及模型可见上下文通过原生持久化路径记录，再开始模型请求。
5. 工具从本次执行上下文取得业务对象和运行目录，通过作者提供的 MCP、CLI 或业务服务操作数据。
6. 由业务数据变化通知更新视图；返回结果明确成功、失败或结果未知，不能用 UI 切换代替执行确认。

异步准备失败或被取消时，保留输入和引用，给出可重试的具体原因。若对象版本变化影响写入，作者定义冲突检测和恢复策略；宿主提供固定目标和错误传递，不替业务数据库决定合并方式。历史模型输入必须可从会话记录重建，不能只从实时界面或内存中补取已变化的选区。

专家环境按会话激活，工具绑定不可依赖全局“当前打开的工作台”。随包依赖必须显式声明，不扫描任意目录自动加载。准备过程应可观察、可取消并避免重复加载同一版本；更新后的环境何时用于已有会话必须明确，不在运行中的一轮里切换实现。

## 8. 生命周期与失败处理

| 作用范围 | 典型贡献 | 释放时机 |
| --- | --- | --- |
| 安装记录 | 包身份、版本、资源位置、启用状态 | 卸载包；业务数据按独立规则保留 |
| 启用的工作台 | 设置、已声明的全局命令、Host 服务 | 停用、升级替换或卸载 |
| 活跃视图 | 主视图、顶栏、选择状态和界面订阅 | 视图关闭或重新绑定 |
| 关联会话 | 专家环境、工具、会话级服务 | 解绑、会话释放或依赖替换 |
| 当前轮次 | 固定目标、引用快照、请求和取消信号 | 本轮完成、失败或取消 |

所有注册都返回释放函数并接入 Cordis effects。相同贡献标识重复注册应明确失败；部分激活失败要撤销已经注册的内容，不能残留半套菜单和工具。界面错误由工作台视图隔离并提供恢复入口，后台服务错误由对应服务报告；插件所在进程崩溃不属于组件错误隔离的保证范围。

停用、卸载和升级先确定是否有活跃调用，再执行明确的等待或取消流程，确认资源释放后切换版本。无法确认执行是否完成时必须报告结果未知，不能把安装完成显示成运行已生效。首次实现应采用可解释的一致规则，避免为了热更新让同一轮混用两个版本。

多窗口下的视图状态各自独立；共享业务数据的并发由作者处理。延迟返回的异步结果只能更新它所属的视图、会话和对象，不能覆盖后来打开的工作台。卸载后保留可阅读的会话与引用快照，失效的业务跳转明确显示不可用。

## 9. 存储、身份与权限

宿主继续提供稳定的业务数据目录、只读包资源目录和可清理缓存目录。业务数据不放在随版本替换的包目录里。作者可以选择 JSON、SQLite、普通文件或远程服务，并负责数据迁移、备份、锁和冲突；需要轻量存储的作者仍可使用现有 JSON 适配器。

宿主只管理运行所需的信息：安装与版本记录、配置、能力授权、会话与业务对象关联、布局偏好，以及原生会话日志。更新和卸载默认保留业务数据；清理业务数据是独立操作，明确范围并确认。回退代码版本不能自动承诺业务数据也可回退。

身份接口提供当前用户、组织和登录状态等公开信息；平台请求通过宿主受控能力完成。已有模型目录能力可复用，新的生成、计费或其他平台 API 需要另行定义，不能把长期 token 暴露给工作台前端、专家提示词或工具输出。远程登录失效只影响相关平台能力，本地业务与离线数据应继续可用。

能力声明用于安装解释、运行检查和服务授权，不应宣传为任意插件代码的强隔离。完整 Host/Client 扩展按受信任插件管理；未来如接收不可信代码，应单独设计进程或沙箱隔离及通信协议，不能仅凭增加权限字段宣称安全隔离完成。

## 10. 兼容与迁移

现有工作台注册、原生对话接入和 JSON provider 可以通过适配层继续运行，逐步迁移到统一 SDK。新协议以一个明确的版本解析步骤决定所需能力，不在各个调用处静默猜测旧字段。现有数据目录与工作台身份保持稳定，迁移前后会话应继续指向同一份业务数据。

先补齐宿主扩展接口，再迁移参考工作台和开发模板，最后移除已被替代的专用实现。不得要求作者通过私有 DOM 操作补齐 SDK 缺口；暂不支持的能力应在校验或激活时给出明确说明。

新增持久化关联或模型可见上下文时，按仓库持久化类型确认和 Session 格式规则执行；可被外部感知的不兼容变更同步写升级指南。格式合法、构建成功、安装成功、加载成功和真实业务验收分别记录，不能相互替代。

## 11. 分阶段交付与验收

| 阶段 | 交付内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| 一：协议与生命周期 | 工作台包声明、服务职责、作用范围、版本解析和现有实现适配 | 一个现有工作台经统一注册运行，重复注册和部分失败可正确释放 |
| 二：宿主 UI 扩展 | 顶栏、面包屑、命令、设置、原生输入引用与历史展示适配 | 工作台无需改宿主源码即可扩展这些区域，关闭后无残留 |
| 三：业务对象与 AI | 对象恢复、关联会话、提交准备、专家依赖和工具上下文 | 普通会话不继承；多对象、多窗口、异步发送不串用目标 |
| 四：安装与版本闭环 | 包校验、启停、更新、回退、卸载、活跃调用处理 | 更新失败可恢复，运行状态准确，业务数据和历史记录保留 |
| 五：开发者交付 | SDK、脚手架、示例、开发 Skill、可选视觉规范、检验命令 | 新目录可完成初始化、开发、校验、打包、安装和加载验收 |
| 六：通用性验收 | 协作白板和另一种非画布工作台的独立开发验证 | 两类工作台均不依赖私有补丁，并完成约定业务流程 |

阶段二和三共享输入引用设计，协议评审时一并确定；实现可按依赖顺序交付，不以单个组件完成宣称整体架构完成。每阶段覆盖正常流程、停用/卸载、取消、失败和恢复；涉及模型输入的变更补充可重放的会话快照。macOS、Windows、真实账号和离线场景分别记录实测证据与待验证项。

阶段一的验收入口为[生命周期与兼容回归](../packages/actvero/capability-ui/tests/workbench-runtime.spec.ts)、[开发命令测试](../scripts/actvero-workbench.client.spec.ts)、[真实安装与重启测试](../apps/web/tests/actvero-workbench-manager.e2e.ts)和[准备失败的原生会话回放](../apps/web/tests/actvero-workbench-lifecycle.snapshot.ts)。模板、开发 Skill 和包预检共用同一兼容声明；现有省略声明的工作台仍按原始扩展 API 运行。阶段二的顶栏已通过原生 keyed Slot 和工具栏 Factory 接入，支持自定义组件、面包屑与共享视图 Store，AI 模板已移除重复标题和通用 AI 按钮。显式输入引用适配已通过 API 1.2.0 接入，验收入口为[引用事务测试](../packages/actvero/capability-ui/tests/workbench-reference.client.spec.ts)和[引用会话回放](../apps/web/tests/actvero-workbench-reference.snapshot.ts)。API 1.3 已接入原生设置页与关联对话命令：支持打开指定设置页、注册失败回收、停用菜单释放以及选择前的关联复核；验收见[命令作用域测试](../packages/actvero/capability-ui/tests/workbench-commands.client.spec.ts)及上述真实安装测试。通用全局命令仍由宿主提供，工作台贡献的命令限于其关联对话。自定义消息和工具结果的工作台封装、自动选区附带及业务对象绑定尚未完成。

开发入口延续现有 create、doctor、typecheck、build、check、pack 和 bind 工具链，补充宿主兼容、依赖、资源、真实加载和释放检查。开发 Skill 说明入口选择、目录、扩展注册、数据职责、AI 生命周期和验收步骤；前端 Skill 单独提供可选视觉标准，默认复用 DSH 原生语义与组件，允许业务视图个性化。

参考白板用于检验图纸列表、编辑页顶栏、选区引用、关联对话和业务数据恢复；再用非画布场景检验设置、命令和自定义存储，避免框架只适配白板。生成图或静态截图只用于设计对照，不能替代插件真实运行证据。

## 12. 本阶段范围

本阶段完善本地工作台的标准运行与宿主扩展，不实施平台投稿审核、远程市场运营、跨设备同步或统一业务数据库。保留未来远程目录下载同一工作台包的接口位置；这些后续能力不应阻塞本地开发、安装和使用。
