# 工作台运行生态实施规划

[English](workbench-runtime-plan.md) | 中文

本文面向实现工作台宿主、开发工具和专家集成的研发人员，用于拆分本地运行能力、安排交付顺序并逐阶段验收。状态：第一部分运行目录、可选存储和 AI 开关，以及第二部分随包专家加载已实现，已通过隔离客户端、真实 Desktop Host 与专项回归测试；Windows 运行验收待执行。第三至六部分仍为待实施目标，当前包格式和调用方式以[工作台开发指南](workbench-development.zh.md)为准。

## 摘要

分为六部分实施：运行环境与数据目录、AI 与随包专家、界面控制与 Agent 工具、身份与平台访问、开发工具链、开发 Skill 与端到端验收。优先完成前两部分；现有包管理和界面继续复用，平台发布与分发后置。

## 设计范围

宿主提供稳定的运行环境和可选能力，工作台作者决定界面、业务流程、数据结构、存储技术以及 AI 操作业务的方法。无需 AI 的工作台应能直接打开、使用和保存，不必先建立对话或选择工作区。

| 归属 | 负责内容 |
| --- | --- |
| 宿主 | 安装与版本、运行目录、界面承载、原生对话、权限执行、公共身份上下文、平台请求通道 |
| 工作台 | 业务页面、存储选型、项目组织、数据迁移、业务操作与状态刷新 |
| 随包专家 | 指令、Skill、MCP、CLI 使用方式及当前业务上下文的组织 |
| 用户 | 选择工作台、授权实际访问范围、选择显示方式和是否使用 AI |

本轮不建设平台工作台市场、投稿审核、远程分发、自动更新或跨设备业务数据同步；也不要求作者采用宿主统一的项目表、数据库或业务操作协议。

## 现有基础

以下基线来自源码和现有开发指南核对，不替代各阶段的运行验收。

| 已有能力 | 后续处理 |
| --- | --- |
| 本地包生成、打包、校验、导入和版本管理 | 复用，随新接口补充兼容性校验 |
| 工作台管理页、业务页、AI 浮窗、对话中的工作台预览 | 复用，统一公开的显示控制方式 |
| 原生会话绑定、专家指令、显式业务工具 | 扩展为可选 AI 和完整随包专家加载 |
| 稳定实例、自定义业务目录与可选 JSON 适配器 | 已接通；供后续专家与工具集成复用 |
| 公共账号信息读取 | 补充受控的平台请求能力 |

实现入口主要在[工作台能力包](../packages/actvero/capability-ui/README.zh.md)。Host 接口支持自定义存储和可选 `storage` 适配器，旧式 `initial()`、`reduce()` 与 `actionHelp` 保持兼容。只有 JSON 适配器托管业务状态；自定义存储自行组织业务项目。通过 `environment()` 可在无会话时查询稳定数据目录，原有实例、目录与关联事件保持有效。

## 第一部分：运行环境与数据目录

目标：作者拿到稳定的本地保存位置，自行决定保存什么、如何保存，以及是否在其中创建多个业务项目。

### 交付内容

- 提供统一运行上下文：工作台标识、安装版本、只读资源目录、可写数据根目录，以及可选的会话关联信息。未启用 AI 时也能取得运行上下文。
- 数据根目录由宿主管理并稳定解析，不使用插件安装目录、当前进程目录或临时解包目录保存业务数据；升级和重新加载后路径保持稳定。
- 作者可以在根目录中使用 JSON、SQLite、文件等，也可以使用远程服务。宿主不复制一份业务状态作为第二个权威数据源。
- 将现有 JSON 状态与动作处理实现保留为可选适配器；需要它的清单类工作台继续使用，其他工作台无需实现空的 `initial/reduce`。
- 保留现有实例标识、目录和会话关联。新接口通过兼容适配接入；确需迁移持久化格式时单独提供迁移方案和升级说明。
- 卸载默认保留业务目录，清理数据作为单独操作。安装代码的版本回退不承诺自动回退业务数据格式。

一个数据根目录不等于一个业务项目。作者可以自行在其中建立多个项目，并决定每条对话使用哪个项目；宿主只保存必要的关联标识，不定义项目表结构。会话工作目录、业务数据目录和文件访问权限分别处理：获得目录路径不代表 AI 自动获得任意文件访问权限。

### 验收标准

无 AI 工作台可独立运行；两个工作台的数据互不覆盖；现有项目清单升级后数据与关联对话保留；自定义文件存储示例可在重启后恢复，且无需写入宿主通用 JSON 状态。工作台自己的并发写入、事务和业务数据迁移由作者负责，框架文档明确这一责任。

<a id="ai"></a>

## 第二部分：AI 与随包专家

目标：作者通过少量配置启用原生 AI 对话，由随包专家决定如何理解和操作工作台。

### 交付内容

- 声明是否启用 AI，以及可选的专家入口；没有专家包时仍可使用普通 AI 对话，专家不必绑定独立模型，默认使用会话模型。
- 将专家加载接入已有专家、Skill、MCP 和命令执行体系，明确包内资源、已安装依赖和需要额外安装的依赖，不另建执行引擎。
- 在关联会话中加载专家指令与声明的能力，传递当前工作台、数据目录及作者提供的业务上下文；不默认把整个业务目录发送给模型。
- 作者可选择直接业务工具、MCP、Skill 配合 CLI 或文件操作。框架不要求所有操作都经过通用 JSON action；界面通过作者定义的刷新方式读取更新后的数据。
- 依赖按包版本解析和缓存；会话记录使用的专家版本。版本变化、依赖缺失、启动失败或授权不足时提供明确状态，取消加载后不残留会话工具。
- 切换工作台、取消关联或结束会话时释放对应能力；重试和重复打开不重复注册工具，不让旧工作台上下文进入其他会话。
- 专家指令、业务上下文及工具结果凡进入模型请求，都通过现有会话日志机制记录，确保可追溯。

“随包专家”在产品上可不占用普通专家选择标签，但其指令、能力和权限仍能查看。打开浮窗本身不发送消息、不自动执行业务操作；模型凭据和权限继续由宿主处理。

### 验收标准

至少用“显式业务工具”和“Skill 配合 CLI”两种方式验证 AI 修改同一份业务数据并刷新界面；验证一个随包 MCP 的加载与释放；覆盖依赖缺失、离线缓存、加载取消及会话切换。未开启 AI 的工作台不启动这些依赖，两条无关对话不会获得对方的工具或项目上下文。

本地实现已接通 `WorkbenchProvider.activate` 与 `WorkbenchExpertBundle`。包内资源按工作台版本解析，已安装 Skill 固定摘要并重新检查原生授权；会话单独注册 Skill/MCP，并在取消关联、提供者卸载与原生会话退出时等待释放。真实 Host 验证业务工具、Skill/CLI、MCP 修改同一份文件，并记录工具结果。平台依赖引用、依赖自动安装和 Windows 原生 shell 的等价验收仍需单独处理。

<a id="presentation"></a>

## 第三部分：界面控制与 Agent 工具

目标：用户和 Agent 都能打开工作台、选择显示方式和继续原有业务，而不需要重复建立会话或数据。

### 交付内容

- 统一已有的业务主界面、对话主界面、工作台悬浮预览和 AI 浮窗，并向工作台作者提供可调用的显示接口。
- 提供进入工作台时的布局建议：保留侧栏或专注展示业务；用户可调整并记忆。隐藏侧栏与操作系统全屏分开，离开工作台时恢复合理的宿主布局。
- 分别保存 AI 浮窗与工作台预览的开关、位置等展示偏好；首次展示使用声明的默认值，用户后续选择优先。收起窗口不取消工作台关联。
- 新建、切换关联对话时继续使用对应的工作台和作者选择的业务上下文；纯业务操作不因打开页面而强制创建会话。
- 增加常驻 Agent 能力：列出可用工作台、打开指定工作台、查询当前状态、调整显示方式。共用界面操作入口，避免另写一套导航和关联逻辑。
- 打开操作返回实际确认状态。前端未连接、工作台加载失败或请求未完成时，不报告“已打开”；重复请求应复用已有实例和视图。

### 验收标准

在 macOS 和 Windows 验证进入、退出、侧栏恢复、浮窗收起、位置记忆以及关联会话切换；Agent 打开工作台后能读取到与界面一致的状态。窄窗口保留公共入口，预览不遮挡关键操作，显示方式切换不丢失业务上下文。

<a id="identity"></a>

## 第四部分：身份与平台访问

目标：工作台可以复用当前登录身份请求已授权的平台服务，同时保持本地业务独立可用。

### 交付内容

- 统一提供用户、组织、平台环境及授权能力的公共信息；明确未登录和无权限状态，不返回长期登录凭据。
- 提供由 Electron Main 管理鉴权的平台请求通道，先接入一个真实服务，例如读取当前用户可用的图片或视频模型目录。
- 平台服务按工作台声明和用户授权限制访问范围；第三方服务由作者自行集成，不把宿主登录凭据传给任意地址。
- 用户退出登录、切换组织或平台后，清理或重新解析关联请求与缓存；业务数据是否按账号分开由作者决定，框架不静默搬移本地文件。

### 验收标准

本地功能在未登录或离线时可用；受保护服务在未授权时有明确提示；切换组织后不能复用上一组织的资源授权；业务前端、模型上下文和日志不出现长期令牌。此阶段不包含工作台平台发布。

<a id="tooling"></a>

## 第五部分：开发工具链

目标：研发人员和使用 Agent 的用户都能从固定入口创建、调试、打包并安装自己的工作台。

### 交付内容

- 延续现有 `create`、`pack`、`check` 工具，不另造重复命令；提供“普通业务界面”和“带 AI 与专家”的最小模板。
- 在管理页提供明确的开发入口，连接开发指南、模板和本地导入；创建时不要求 GitHub 账号或仓库。
- 明确最小包组成：元信息、页面入口、资源；按需增加 Host 服务、专家包和依赖声明。AI、云服务、通用 JSON 存储均为可选。
- 提供本地开发预览、加载错误、依赖状态和包校验结果；将包格式、宿主接口版本和数据格式版本分别说明。
- 把路径、版本、入口、资源与依赖完整性纳入检查。保留现有压缩包支持范围，是否增加 ZIP 由实际导入需要单独决定，不把 ZIP 支持作为本轮开工条件。

### 验收标准

研发人员从空目录按指南生成两个模板，分别完成构建、校验、导入和实际加载；无需修改宿主源码。缺少入口、依赖不匹配或包结构错误时能定位原因，失败安装不破坏已有版本和业务数据。

<a id="skill"></a>

## 第六部分：开发 Skill 与端到端验收

目标：将实际可用的接口、开发流程和自测方法沉淀为可复用的工作台开发 Skill。

### 交付内容

- 开发指南作为接口事实的唯一说明入口；Skill 引用指南和模板，负责需求确认、存储选择、AI 配置、开发、校验、安装与验收流程，不复制一套易过期的接口文档。
- Skill 明确业务需求后才创建业务代码；允许作者自由选择前端技术、存储和工具方式；对模型、网络、安装依赖及权限做真实检查。
- 用一个纯本地自定义存储示例和一个带随包专家的示例覆盖完整流程；复用现有项目清单做升级兼容验证。
- 完成无会话、已有会话、多业务上下文、离线、重启、更新、停用和卸载保留数据的验收记录；区分静态校验、真实加载和真实 AI 操作。

### 验收标准

在干净的隔离开发环境中，仅凭 Skill 和开发指南完成工作台开发与安装；普通业务无需 AI 也能运行，AI 能通过专家选择的工具修改数据，恢复会话后仍能找到正确业务内容。未经实际执行的检查明确标为待验证。

<a id="delivery"></a>

## 交付顺序

| 顺序 | 可交付结果 | 前置条件 |
| --- | --- | --- |
| 1 | 自定义存储的普通工作台可稳定运行 | 复用现有包管理 |
| 2 | 可选 AI 与完整专家依赖可用 | 第一部分运行上下文 |
| 3 | 用户和 Agent 可一致地控制工作台显示 | 前两部分的会话与上下文接口 |
| 4 | 当前账号可请求已授权平台服务 | 第一部分上下文及已有登录体系 |
| 5 | 模板、调试和包检查形成标准入口 | 前四部分接口已稳定 |
| 6 | 开发 Skill 与完整验收闭环 | 工具链和参考示例可实际运行 |

每部分交付时同步更新开发指南、相关模板和对应检查；第五部分集中完善开发体验，第六部分才定稿 Skill。先完成第一、二部分，就能验证核心目标：作者自由实现业务和存储，按需获得宿主 AI 能力，并用自己的专家和工具操作工作台。
