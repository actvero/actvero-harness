# Actvero 客户端工作台

[English](workbenches.md) | 中文

本文面向维护 Actvero 桌面客户端的开发者，用于启动工作台预览、接入本地业务工作台，并判断安装和运行结果。

工作台运行上下文、可选宿主能力及内置本地专家的后续设计见[设计记录](../.agents/notes/proposed/architecture/2026-11-05-actvero-workbench-runtime.zh.md)。该记录明确设计方向，不表示统一开发接口已经发布。

从可编辑模板生成独立安装包的步骤见[本地工作台开发](workbench-development.zh.md)。

## 启动和入口

完成依赖安装后，运行 `pnpm run actvero:dev`；已有最新构建时运行 `pnpm run actvero:start`。这两个入口使用独立开发数据，不读取已安装客户端的账户和会话。展开左侧栏，点击「DSH 工作台」打开兼容市场；右侧名称区域可切换普通会话与已加载的兼容工作台。「已安装」显示本地包及其实际运行状态。

「工作台」打开 Actvero 的「我的工作台」。可以搜索、打开内置的「项目清单」或导入本机的 Actvero 工作台包。分类栏仅在平台目录显示，不筛选「我的工作台」。导入后的卡片显示安装版本和运行状态，停用后仍保留，安装结果若提示重启，请使用「Harness → 重启 Harness」。「DSH 工作台」进入兼容的市场和旧工作台入口。

点击侧栏左侧「工作台」进入管理页；点击同一行右侧名称，打开「我的工作台」菜单并直接切换已加载的工作台。菜单包含内置「项目清单」，当前选择带勾选标记，长名称截断后可悬停查看。返回管理页或刷新后仍记住上次选择，刷新不强制跳转业务页。未加载或已注销的工作台不在菜单中显示。

打开后，业务组件使用右侧主内容区，首次不创建会话、不要求选择目录。支持 AI 的工作台提供「AI 协助」和「新建工作台对话」入口；原生会话通过「＋ → 工作台」选择后，输入框显示工作台徽标，右上角可悬浮查看或进入完整工作台。收起保留关联，取消使用移除该会话的工作台能力；再次打开已有会话会恢复所选工作台。运行接口与数据规则见[本地开发说明](workbench-development.zh.md#native-ai)。

在「平台工作台」选择组织已授权的发布，点击「使用」下载并安装。工作台加载后进入业务页，并出现在「我的工作台」。再次点击「打开」时复用已安装版本。发布新版后可选择「更新并打开」，或通过更多菜单打开仍获授权的已安装版本。安装或更新提示「待重启」时，重启 Harness 后再打开。撤回发布或失去权限后，已安装工作台仍可卸载，打开时会提示不可用。

「我的工作台」显示已添加工作台的来源及运行状态。卡片预览与详情缩略图可横向滚动，不显示滚动条或图片数量；卡片两侧箭头在鼠标悬停或键盘聚焦时显示，触屏上常显。点击卡片打开详情，点击缩略图定位到对应预览。详情左侧展示图片，右侧集中展示介绍、来源、版本、已提供的作者与打开按钮，窄窗口按上下排列；预览和缩略图保留边框，选中图片高亮。详情缩略图从左侧排列，通过点击缩略图或左右方向键切图，不显示前后按钮；单图隐藏缩略图，点击大图可放大查看。预览由工作台提供，不是当前项目的实时画面。

Actvero 本地包使用 npm 打包的 `.tgz`。包清单声明 `dsh.actveroWorkbench: 1`、bundle patch 和客户端入口，并声明客户端依赖 `@actvero/dsh-capability-ui`。客户端插件通过 `ctx.effect(() => ctx.actveroWorkbenches.register(descriptor, Component))` 注册卡片和业务组件。安装由当前 Profile 的插件管理器执行，打开业务页时使用已注册的组件。

## 宿主和业务包

工作台宿主采用 DataElement 的 DSH Desktop 源码，MIT 许可及固定来源见 [第三方来源说明](third-party/dsh-desktop-workbenches/UPSTREAM.md)。宿主保留工作台主页、市场目录、收藏、切换、安装状态，以及业务面板与原生 AI 会话的组合方式。「DSH 工作台」的兼容市场读取 DSH 公开目录；「平台工作台」读取登录组织的授权目录。

业务工作台是独立的 DSH bundle。客户端加载包后，业务插件通过 `ctx.desktopWorkbenches.register(descriptor, Component)` 注册并返回注销函数；插件必须以 Cordis effect 管理注册。纯本地包可以省略仓库地址，宿主根据包名生成稳定身份。详细包格式和布局规则见随源码保留的 [上游开发规范快照](third-party/dsh-desktop-workbenches/)；快照不是在线最新规范。

普通分栏由宿主同时展示业务面板与原生会话。业务整页模式由业务组件安排首次使用入口，需要 AI 协助时调用宿主的会话接口并放置宿主提供的会话节点。客户端通过原生插槽和 Factory 组合会话，没有复制另一套聊天界面。侧栏过滤只影响展示；Session、Workspace Controller 的原始目录保持完整，普通会话与工作台会话各自保留。

## 安装和版本限制

本地工作台安装走当前 Profile 的 Plugin Manager。安装结果、插件运行状态、左侧切换入口和真实业务界面需要分别检查；安装成功不代表全部验收通过。Actvero 自有工作台支持确认后更新同名包、启停和卸载，操作步骤与数据保留规则见[本地开发说明](workbench-development.zh.md#install)。旧 DSH 市场适配层仍拒绝直接覆盖，提示通过插件管理先卸载再安装，不自动删除插件。市场包若要求更高的 Harness 版本，仍由兼容性检查拒绝。

npm 市场包先按目录提供的 SHA-512 校验下载内容及包名、版本，再作为本地归档交给 Plugin Manager。原生安装审批和插件兼容性检查继续生效。业务工作台的账号、网络和文件访问能力仍由其自身及宿主策略决定。

## 开发验证

`apps/web/tests/actvero-workbenches.e2e.ts` 使用真实 Desktop Host 和临时本地工作台包，检查已安装列表、切换、首次无会话入口、按需打开原生对话、刷新恢复以及浅色、深色和较窄窗口。示例包只存在于临时验收 Profile，不作为业务工作台随产品发布。工作区导航测试检查会话归属、空白会话复用及过滤贡献的注销。

构建与类型检查遵循仓库的 `build:artifacts`、`build:check` 流程。浏览器验收不替代签名安装包、真实组织账号和模型请求验收。
